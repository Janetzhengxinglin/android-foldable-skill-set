# 逐页可见对象检查

在清晰整页巡检时使用，不另设一次全量看图。先看实际对象，再映射规则；用户指出的问题只是补充线索，不能代替全页发现。

| 对象 | 必须观察的内容 | 对应判据 |
| --- | --- | --- |
| 页面与固定区域 | 实际 App 窗口、根背景、正文、顶部和底部操作分别检查；可见越界、遮挡与留白各自判断 | window.fit、obstruction.visible |
| 所有可见文字 | 标题、金额、标签、按钮、导航、菜单、输入，以及图片里绘制的文字；观察缺字、半个字、重叠、不当换行和可辨性 | text.composition、window.graphics；不是只检查原生 Text 组件 |
| 每张媒体／广告／奖励卡 | 分别观察容器边界、内嵌文字、标志、主体及周围控件；多张卡不能只登记一个“媒体区”来代替逐卡检查 | 文字走 text.composition；有参照的变形／明显模糊走 window.graphics；窗口越界走 window.fit |
| 已出现的输入、菜单、弹层 | 各项内容、按钮、边缘与键盘／固定栏关系；检查当前显示，不能推导操作失败 | text.composition、components.visible、obstruction.visible |
| 图标与主题 | 系统区域和 App 自有区域分开；已确认的系统栏／展开手柄不计为 App 控件缺陷；观察可见图标、文字与背景是否能区分 | window.graphics、accessibility.themes；截图不推算真实热区或数值对比度 |

## 裁切的三个边界

1. **视口边缘**：内容整体随滚动进入或离开视口，可以正常。只回查该区相邻帧；固定底栏遮挡是否持续到滚动终点，需要对应证据。
2. **媒体／卡片容器内部**：文字在容器边界缺字、半字，即使写在图片像素中也要检查。页面滚动不会修复容器内部裁切，不能套用滚动例外。横向轮播露出的下一张卡须区分“整卡尚未进入视口”和“当前完整卡内部截字”。
3. **图片构图**：每张图主动检查主体，先区分装饰背景、主体局部取景，以及表达任务／优惠／产品所必需的信息。普通主体裁切不自动违反 Google 基础要求；只有可证明的信息截断、窗口越界或有参照的失真才按相应强制条款判错。无法确定主体是否应完整时保留观察及缺口，不能报“所有图片必须完整”。

没有源素材不妨碍确认当前图片里的半个字或互相重叠；但不能据此猜测原素材长什么样、实现原因或正常比例。宣传标题故意省略、独立短标签和摄影构图须依据当前图像核对，不能补写未知文字。

## 记录与退出

复用现有组件库存与 visual_observation：给每张卡／图稳定身份，简短记录文字、主体和边界观察；需要单独定位的内嵌文字可建 text 子项，或由 media／card 检查项直接承载。不得同时为父子对象重复建立同一问题。没有疑点的同类对象可合并写观察，不制造每对象多轮签核表。

读不清或有疑点时看对应原图／局部及必要相邻帧；据实际证据作 issue、no_issue_observed、not_applicable 或 not_verified。条件不足只阻断依赖该条件的结论，不要求找到代码、API、源素材或另一设备才结束整份审查。
