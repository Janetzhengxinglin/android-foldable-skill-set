## 官方要求层级

[Tier 3](https://developer.android.com/docs/quality-guidelines/adaptive-app-quality/tier-3) 明确 Adaptive ready 先满足 Core app quality，尤其 User experience；Tier 3 是折叠屏和大屏的基础质量标准。因此 Core 不是可忽略的低优先级要求。

## 检查顺序与问题影响分开

Google 文档给出质量层级、类别和测试 ID，没有为这里每类截图缺陷定义 P0／P1 严重程度。以下顺序是基于官方类别依赖安排的截图执行顺序，不冒充 Google 严重程度：

1. 按窗口与配置要求确定可用显示区；检查整页及实际遮挡。
2. 按 Core Visual quality 的图形、文字、主题类别检查所有可见对象，含图片内文字；弹层和输入的文字也在这里检查。
3. 按已出现的状态核对弹层、键盘、媒体等条件及例外，定点复查疑点并汇总。

规则的 priority=1／2 是现有工作流的检查／处理顺序字段，兼容保留，不能称为官方缺陷等级。金额、关键信息或主要操作已受影响时优先处理，是项目的影响判断，须写出实际受影响内容；其余成立问题仍全部检查、保留。不要用严重程度筛掉应审页面，也不要按 Duo／Apple 规则排列安卓要求。
