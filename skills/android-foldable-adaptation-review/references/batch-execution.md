# 默认批量审查

默认 screenshot-only 使用 batch：**批量抽帧 → 集中看图 → 疑点打开原图 → 生成记录 → 核对问题和报告**。不设独立全量人工质检，不要求全部原图重读两遍。用户明确要求严格双轮审查时使用 two-pass；旧审核记录未声明策略时仍按 two-pass 校验。

- 脚本核对来源、尺寸、hash 和候选覆盖，顺序解码抽帧；独立视频可并发处理。集中看候选拼图并核实同状态重复映射，只对短暂状态或疑点补帧。
- 完整清单中的每页都进入视觉巡检。可用清晰整页成品拼图；文字、图标或边界读不清时打开该页原图／细节，不用小缩略图猜判断。看图时同时确认选帧、清晰度、脱敏和适配，无需把同图分成三个独立读取阶段。
- 按流程连续观察文字、控件、媒体、导航、边界及组件关系，集中保存 observations.json，再用 prepare／seed 生成正式检查骨架并映射真实观察。未看的页不写完成，不从问题列表反向生成通过。
- 复查集中于已确认问题、疑点、易漏的弱对比图标／长文本／组件交界，以及报告位置和编号。无新疑点的正常页不强制再次读原图。报告的每项已确认问题都须回查原始证据。
- 一次校验覆盖、来源、规则和报告映射，再统一发布回读。候选、窗口、方向和独立状态不因拼图展示合并丢失；规则仍是 Google 基础适配。

batch 的 review.json 使用 review_strategy="batch"；visual_review.page_ids_reviewed 记录真实巡检过的全部页面，notes 说明拼图和必要原图范围；self_review.finding_ids_rechecked 记录实际回查的全部已确认问题，notes 说明疑点及报告核对。没有独立双轮就不填写 all_pages_rechecked／all_components_rechecked 为 true。正式字段只记录实际完成，脚本不证明视觉判断准确。

拼图用采集 skill 的 scripts/review_sheets.py 从受审整页原图生成，manifest 保留每页路径、hash 和格位。按清晰度与图片预算决定每图页数，不照抄历史拼图密度。读取仍执行 image-processing.md 的数量、像素和累计预算；任务按流程连续执行，不为每几张图创建执行者或交接文件。单智能体不维护分工收据。

证据不足保存具体缺口并继续其他页面，不记通过或确定缺陷。原图、历史报告和修订映射保留；证据改变重审受影响判断。需要 two-pass 时执行两轮全部原图与组件检查，其完成门槛继续由脚本保留。

复审在本轮独立观察后与旧稿逐项对账：每个旧审查项保留、重新分类或写出排除依据；“未确认违规”不等于“现象不存在”，用户保留的待核实项和展示观察不能无说明消失。同时对照旧页面清单，短暂页面未进入新采集时定点补帧，不重读全部正常页。
