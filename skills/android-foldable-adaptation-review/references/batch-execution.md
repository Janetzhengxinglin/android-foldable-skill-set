# 集中批量审查

批量录屏采用集中选帧、集中观察、批量生成记录、统一报告的流程。平台判断沿用安卓 screenshot-only，不引入苹果规则或历史问题类别。

1. **一次收齐与抽帧。** 解析文档全部录屏和屏幕标签；同源素材下载一次。独立视频的下载、抽帧、hash、拼图可用脚本并发，按机器资源限制并发量，不为文件处理创建审核子任务。来源和标签不明时只核对必要信息。
2. **集中筛选页面。** 按录屏与流程顺序看候选拼图，完整分类并选择清晰代表帧。核对页面、方向、窗口、内容和固定层关系后，将同状态的重复滚动／进入画面映射到代表帧；新组件、键盘、菜单、弹层、错误和独立布局状态保留。只有短暂状态、清晰度或稳定性疑点才定点补图，不给每张图固定追加前后帧，不把连续运动中的每个取样点变成独立受审状态。全部来源及区间覆盖在采集数据中一次整理。
3. **集中看图与记录观察。** 完整截图交接后，按业务流程和屏幕分组连续读取清晰原图，逐页查看文字、控件、媒体、导航、边界及组件关系。用一份 observations.json 保存页面 ID、证据 hash、实际检查的组件范围、可见发现或明确无异常结论。相关疑点集中核对安卓条款与例外；常规引用已核查快照，不重读全部来源。不为每个组件另建任务、另写长段解释或单独调用校验。
4. **批量生成记录与复查。** 组件和基础观察确定后，用现有 prepare／seed 生成检查骨架，再将真实观察按页面、组件和规则映射到正式检查项。共享事实和引用由脚本展开；无异常组件可简短记录。未观察的项保持未完成，不能仅凭不在问题列表中自动填通过。第二轮连续回看全部受审原图，集中记录新增、撤回和保留发现，修订受影响记录。
5. **一次汇总与交付。** 归并同类问题、完整保存发生位置，集中选择对应官方示例并批量排版。完成后统一校验清单、引用、两轮覆盖和报告映射，再发布及回读；输入改变或校验失败时只重验受影响结果。

默认由主智能体连续完成关联流程。需要分工时只拆独立录屏或完整业务流程，各自连续执行一段完整工作，不建立质量、补帧、预审、修补等多层细碎队列。分工时才读 agent-coordination.md 和使用交接收据；单智能体不额外维护分工文件。

图片调用仍遵守采集 skill 的 image-processing.md。读取批次不等于工作任务：一个流程可以包含多个安全的小批读取；观察及时保存，流程结束、阶段切换或中断时保存检查点。脚本预算检查、记账和结果保存可在同一次工具编排中顺序完成，避免额外往返；每次实际读图前的预算检查不能省略，也不能一次返回所有图片。

有清晰可审截图就继续，不因无法证明未展示的动态行为停住。只有运动画面或事实不足时，在内部保存具体缺口，在最终范围说明中如实交代；不记通过或确定缺陷。新证据改变结论时修订相关记录；报告与旧证据保留。现有脚本不会识别页面或替代视觉判断，记录生成和结构校验不证明已完成审查。
