# 官方图示的选择

优先采用直接对应的官方抽象图解，完整示例 App/UI Kit 页面在需要具体结构时补充；执行 [视觉呈现与验收](output-presentation.md) 的逐项对应与紧凑尺度要求。

先按当前屏幕和待解释的条款查图，不能仅因规则表里没有图片就省略。三个官方入口：

- [Android UI Kit](https://www.figma.com/community/file/1478523627015571873/android-ui-kit)：系统栏、设备框、相机、通知等系统模板。
- [Android Adaptive UI Samples](https://www.figma.com/community/file/1539759053650269019/android-adaptive-ui-samples)：不同窗口下的页面与布局示例。
- [Adaptive Design Lab](https://www.figma.com/community/file/1504631597454929506/design-an-adaptive-android-layout)：自适应布局练习及示例。

同时查看当前条款对应的 Android Developers 设计文档、UI Gallery 和公告原图。只选实际核对过的图或 Frame；公开封面及资源描述不等于已经检查模板内部。

## 是否采用：四项条件都要满足

1. **对应问题**：图能解释当前问题涉及的具体要求或设计参考，正向示例也可采用，不要求出现同一种错误。仅因图中也是折叠屏，不能采用。
2. **条件适用**：核对 App 窗口、方向、系统区域、媒体类型等与该问题有关的条件。不要求设备外观完全相同；关键条件不同且无法清楚说明时，不拿来对比。
3. **不会误导**：说明图具体解释什么，避免让读者把多栏、导航样式、字体、颜色和示例间距当成强制要求。图只解释标准，不能代替官方条款和 App 原图证明问题。
4. **内容已核实**：实际查看对应图或内部 Frame，保留官方出处、图示或节点身份与阅读记录。资源封面、目录或组件名称不足以证明内容匹配。

选图由审查者按当前问题判断，不按资源名称固定优先级。UI Kit 的系统区域与安全区可解释 App 与系统 UI 的位置关系；键盘模板只说明输入界面形态，不能单独证明 App 的内容遮挡或边距要求。App 内相机预览的方向和缩放查对应 Camera preview 图示，不能用 UI Kit 的系统相机外观代替。内容越界或截断可查对应官方布局图与 Adaptive UI Samples，但不把示例的多栏当作必选方案。

## 放在哪里

按屏幕画板中的实际问题选图，放在第一段“Google 官方规范示例”，随后展示“App 问题示例”和“问题页面汇总”。每张官方图配简短标准摘要与出处，并明确它解释的问题类型；不添加 App 问题标号。同一图能解释该画板多个问题时只放一次，同一问题涉及不同条件时可以分别选图。没有相关问题时，不为补齐版式放无关官方图。

后台逐问题类型记录四项条件的核对结果、采用或不采用的理由以及它关联的画板与条款。查过相关资源仍没有匹配图时，用明确条款代替并记录缺图原因，不拿无关模板凑图。

UI Kit 能读取并复制对应原始 Frame 或组件时保留原生图层；检查过当前权限和工具能力仍无法复制时，可用已核实的官方文档原图。不要自行重绘、补画或用图片外套 Frame 冒充原生模板。未找到匹配图时可用简短条款，但后台须记录查找结果，不能默认跳过图示核对。

素材、出处、目标 Frame、适用条款和选择理由保存在报告后台。通用示例必须说明具体解释哪条基础要求；其中的分栏、导航形态等不能自动升级为 Tier 3 强制要求。

已核实的通用图片见 assets/official-examples.json。脚本只按规则关联预置图片，不自动搜索或判断 UI Kit、Samples 与课程图是否匹配；生成初稿后仍须按上述条件检查每张画板并补齐合适示例。

设计资源对条件判断和排除误报的用途见同级 android-foldable-design-guidelines/references/design-reference.md。本文件只负责选图，不能代替判断环节读取设计参考。读取范围和未读内容以 design-resource-coverage.json 为准。
